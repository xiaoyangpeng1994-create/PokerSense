# AA 外部本地候选：来源核查与本机可用性筛查

本轮目标是核查两个通用决策模型能否作为**离线研究候选**进入现有扑克评估器。
这不是四街策略强度验收、真实桌规匹配、采集卡端到端时延或实战准入。
用户当前选择：完整四街、6–8人、本地运行、先固定一种常打桌规、稳定建议与局后复盘。

**本机可加载和四街局面查询通过；时延仅形成小样本开发测量；策略强度和实战资格未评估。**
两模型各24个声明查询全部返回合法动作。高精度复测中0.8B为24/24在300ms内，2B为22/24；
前一批测量中两者均有迟到。当前证据不允许将任何一个接入真人建议。

## 输入与运行合同

`ExternalLocalResearchPolicy`只接收模拟环境观察，复用V2精确身份与公开状态校验。
模型获得本人底牌、逐街公共牌、公开行动历史、位置、精确金额、全下／加注重开状态、
公开桌规及原菜单顺序；不转发发牌seed、对手隐藏牌、未来牌、规则来源路径或任意元数据。
提供合法选项分数后按预声明顺序argmax，平局保持原菜单顺序；不补默认动作、不重映射非法金额。
这些分数不是GTO频率或赢钱概率。`INPUT_READY`只表示输入可检查，不能算模型命中。

公开适配器不加载大模型框架，不改变训练器、实时查表工作进程或网页实战资格。
候选运行需要独立研究环境；桌面核心依赖不增加torch/transformers。
`for_game`沿用64个小写十六进制字符的盐合同，盐不进入确定性模型请求。

实际加载使用本地固定safetensors目录、BF16/CUDA/eager，关闭graphs和联网加载；
上游默认1536-token截断不能使用。完整context上限4096，完整prompt上限8192；
超过上限明确拒绝，完整历史与全部选项保留。模型配置、实际导入源码及依赖身份须核对。

## 预先声明的筛查

- 新开发seed为8100000、8100001；仅作为本机工程筛查，不是独立策略强度确认。
- 6/7/8人×此前check/call／首位最小加注两条固定公开路径×四街各首个行动，共24查询；两个候选共48行。
- 所有原始观察、精确身份、请求、模拟规则、资产与运行环境在推理前冻结。
- warmup单列，不计入48行；正式查询每条诊断最多10秒，超过300ms的合法结果记为迟到。
- 每模型另做一次300ms外部截止探针，执行新的forward；不使用决策缓存伪装推理速度。
- 每批最多600秒，包含初始化、资产校验、推理、终止及保存；未执行、模型缺失、超时、OOM、输入超长均保留在分母。
- 本轮没有完整模型对战，因此不得输出完整牌局可执行率、BB/100或盈利结论。

当前默认AA仿真规则仍只是明确的模拟假设。用户桌规未保存／不完整时，不判断真实AA适用性。
不读取保留录像、不启动采集、不调用付费API、不购买云算力、不现场训练或晋升模型。

## 复现入口

准备好独立运行环境和已审上游最小源码／固定模型文件后，在隔离项目根目录执行：

```powershell
$env:PYTHONPATH='src'
$env:PYTHONUTF8='1'
& '<研究环境>/Scripts/python.exe' -m tools.screen_aa_local_policy freeze `
  --output '<全新结果目录>' --model-08b '<固定0.8B目录>' `
  --model-2b '<固定2B目录>' --upstream-package '<已审源码目录>'
& '<同一研究环境>/Scripts/python.exe' -m tools.screen_aa_local_policy run `
  --output '<同一结果目录>' --batch-seconds 600
```

三个批次全部保留：

1. `screen-v1`（25.656秒）：两模型读入权重后被运行器误拒，48条NOT_RUN。上游把没有
   `temperature_by_type`归一化为`{}`，旧校验却要求`None`。已修复并复验；不算模型能力失败。
2. `screen-v2`（39.938秒）：48条合法输出，0.8b22/24、2b12/24在旧计时300ms内；
   两个长河牌截止探针均TIMEOUT，总返回约469ms，其中停止采信与清理分开记录。
   此环境的`time.monotonic`使用15.625ms分辨率的GetTickCount64，不适合阈值精测。
3. `screen-v3`：改用分辨率1e-7秒、单调不可调整的QueryPerformanceCounter并冻结时钟身份。
   与v2为**同一批已暴露开发输入的工程复验**，不是新独立样本，不能合计成96个独立查询。
   模型、全部输出分数和动作、输入与预算均保持一致。

两次运行的后台负载没有严格控制，较快的v3不能归因于时钟修复或视为性能优化收益。
启动前GPU快照为本轮约1657MiB/1%，早期准备阶段约2453MiB/36%；这些瞬时快照也不能
代表完整运行负载。旧较慢结果保留，不能只展示较快一批。300ms是停止采信的截止，
线程调度及工作进程清理仍有耗时；独立阻塞反例记录约302.484ms停止、3.787ms清理、
306.271ms总返回，不能宣称物理执行精确在300ms内结束。

本批每模型包含6个翻前面对价格、18个翻后可免费过牌的脚本状态。0.8b选择6次跟注、
14次全下、4次非全下加注；2b选择6次跟注、18次过牌。14次全下逐条核对目标金额等于
最大raise-to且新增投入等于剩余筹码，没有凭金额猜测。局面来自固定脚本前缀，没有
模型行动后的对手反应，不能据此断言动作错误或模型强弱；它说明下一步必须先做
决策合理性检查与完整对战，不能仅凭输出合法或更快就晋升。

## 独立核对与结论

独立审查已复现运行器身份／IPC截止反例并确认修复，原始故障未抹除。模型实际权重、
本地tokenizer、实际导入模块、配置温度与运行环境绑定均核对；48份已验证prompt与
padding后的forward摘要由tokenizer单独重构，未执行额外模型forward。
聚焦125项测试通过，包含82项适配器测试、真实评估器42个工程正控及无效分数完整失败分母；
这些正控使用测试评分器，不替代真实模型对战。

**0.8b可优先作为下一轮离线完整对战的候选，2b保留为对照；两者均不准入实战。**
优先级依据是本机时延余量，不是已知扑克强度。下一轮须冻结完整牌局、非网格下注、
全下／边池和反制对手测试，先排查机械check/call或无差别全下等行为，再比较完整分母下的收益。
当前真实桌规仍未保存，实际AA适配、完整对战可执行率、对手池收益、真实10秒窗口均为
`NOT_ASSESSED`。本轮到此结束两候选可用性筛查，不继续调参、不增加第三个候选、不训练或购买算力。
