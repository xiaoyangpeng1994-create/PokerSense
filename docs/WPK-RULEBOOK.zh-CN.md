# 德州规则提炼与 WPK 适配底稿

版本：2026-09-08 v1。用途：指导数据标注、状态重建和策略接口；与可执行案例一起维护。
本轮“蒸馏”指提炼规则、明确例外并变成测试，不是训练一个语言模型替代牌局规则引擎。

## 三类知识分开管理

| 类别 | 内容 | 依据与处理 |
|---|---|---|
| 标准 NLHE 规则 | 动作顺序、跟注/加注、all-in、边池、摊牌 | 写成明确场景，使用独立引擎交叉验证 |
| 房间/平台规则 | 前注形式、straddle 位置与金额、抽水封顶与舍入、no-flop-no-drop、暴击/保险/多次发牌 | 以当前房间配置或画面证据确认，不自动套用赛事规则或模拟默认值 |
| 策略 | 范围、下注频率、尺寸、EV、剥削调整 | 来自适用策略源与评估，不能从“动作合法”推导成“动作盈利” |

## 对当前项目最重要的规则

| 编号 | 规则 | 对实现和标注的要求 |
|---|---|---|
| R01 | 在座、仍参与本手、轮到行动是三件事 | 分开记录；弃牌玩家还占座但不能赢底池；all-in 玩家仍有资格但不能继续下注 |
| R02 | 按最佳五张牌比较，最多从两张底牌与五张公共牌中选取 | 可用零/一/两张底牌；公共牌成相同最佳牌可多人平分；有资格人数决定分摊 |
| R03 | 前注是死钱，通常不抵扣本轮跟注；盲注/有效 straddle 属于本轮投入 | `hand_committed` 与 `street_committed` 分开；均摊 ante、BB ante 等形式不能混用 |
| R04 | 跟注金额是额外要付的金额；加注常按“加到”的总额表示 | 若本人已投入 4，面对 12：跟注另付 8；加到 28：另付 24。不能把 raise-to 当作额外投入 |
| R05 | 最小完整加注增量跟随上一笔完整加注，而非永远等于大盲 | 2/4 开局，加到 12 是增量 8；再次完整加注至少到 20。下注轮结束与新街重置也要明确 |
| R06 | 不足完整增量的 all-in 通常不为已经行动者重新开放加注 | 原先加到 12，再有 all-in 到 15；增量 3 小于 8，原行动者面对额外 3 不能因此重新加注。多次短 all-in 的累计情况另建测试，不凭单步简化 |
| R07 | 足额 all-in 可以重新开放加注 | 加到 12 后 all-in 到 20，增量 8；原行动者可再次加到至少 28，前提是还有能继续行动的对手 |
| R08 | 每个边池有自己的资格集合；未被跟注的顶层投入应退还 | 投入 100/60/20，另三人已弃牌：主池 60、边池 80、未跟注退还 40；最短筹码玩家不能赢边池 |
| R09 | 下注轮结束不只是“轮到每个人一次” | 需要依据尚未匹配投入、已行动集合、加注重开及 all-in 状态判断；不能凭按钮消失换街 |
| R10 | 普通多人翻前从大盲左侧开始，翻后从按钮左侧仍可行动者开始；HU 特殊 | 开局 6/7/8 人、翻后剩 2 人不等于重新开始一局 HU；位置与翻前历史必须保留 |
| R11 | Straddle 涉及位置、行动顺序、当前跟注及最小增量 | 本轮示例仅假设 UTG live straddle=8、最小完整加注增量=8；其他位置、可选或特殊 straddle 不自动等价 |
| R12 | 抽水规则影响净 EV，不会直接改变固定牌/范围的摊牌胜率 | 3%/封顶 2BB 仅作示例；在 2/4 桌封顶是 8 筹码。舍入、何时抽、是否见翻牌才抽、保险或暴击费用必须独立确认 |
| R13 | 输赢不能作为单次建议质量的真值 | 正 EV 也会输；负 EV 也会赢。用同节点反事实 EV、策略基准和独立样本长期收益评价 |
| R14 | 严禁使用未来信息形成过去决策 | 未来公共牌、摊牌和客户端揭牌后胜率，只用于校验/复盘；原视频的全量可见信息不能全部喂给历史决策 |

## 已执行的独立案例

`tools/verify_nlhe_rulebook.py` 使用 **PokerKit 0.7.5**，不调用 PokerSense 自身规则函数作为答案：

- 6/7/8 人 × 普通 2/4 或 UTG straddle 8，均为每人 ante 2：初始底池、首行动者、跟注和最小加注，共 6 例。
- 12→15 的不足额 all-in 与 12→20 的足额 all-in：分别不重开/重开，共 2 例。
- 6 人开局三人弃牌，三人投入 100/60/20：主池、边池、资格及退回，共 1 例。
- 200 和 500 底池按 3%、封顶 8 计算，共 2 例。
- 明确选择 no-flop-no-drop 后翻前不抽，共 1 例。

这些案例证明底稿的指定场景与独立引擎一致，**尚不证明生产 StateEngine 已全部实现同样规则**。
下一步要将视频重建的节点送入同样的对照；存在不一致时保留失败，不修改参考答案迁就现有实现。

## 从规则反推视频测试清单

优先提取：完整发牌与强制投入、本人弃牌、本人 all-in、对手 all-in、短 all-in、边池/未跟注退还、结算、补码、换手。
每个节点标出人数、状态、已投入、剩余筹码、当前最高下注、上一完整加注增量、谁已行动、是否可重开。
只有画面能证明的数据才写为事实。例：All in 提示不单独证明其总投入或边池资格；底池栏上的多组数字也不能凭位置猜语义。
