## 已核算的保险窗口

| 画面观察 | 金额/数量 |
|---|---:|
| 有效保险池 | 626 |
| 保险窗“本人已投入” | 313 |
| 投保额与后续“投保”提示 | 174 |
| 显示赔付额 | 313 |
| 显示赔率 | 1:1.8 |
| 总底池 / 四个显示分量 | 1264 / 329+174+626+135 |
| 结算入账增量 | 135、452、503 |

可直接核算：1264−(135+452+503)=174；626−174=452。
这与“投保174”的前后顺序吻合，结算窗口在扣除该保险金额后未解释差额为0。
其中135的退款/未跟注返还语义尚需动作账本确认，不能只由数字相等推导。
显示分量中的174与保险额174是两个独立字段，不能混成同一笔资金。

河牌前、购保提示帧可见 Hero 3dKd、保险对手9c8c、公共牌Kc5dAc9h，
另两家已公开AhQh及2c2d。独立枚举40张剩余牌，得到13张对手胜出牌，
与保险界面列出的13 outs完全一致；实际河牌6h未用于事前outs计算。
174×1.8=313.2，但界面显示313，保留0.2差异，不擅自制定统一取整规则。

这证明一个人工审阅、源帧绑定的保险结算窗口能被程序复核，**不是**已完成自动
保险视觉识别、整手动作重建或平台通用抽水规则。手续费可能在其他时刻体现，
不能从这一个窗口宣称整手无抽水。
