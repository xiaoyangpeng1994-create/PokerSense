# MCCFR checkpoint 恢复的数值一致性修正

## 2026-09-27 修正

CI 的 Python 3.11 在 V1_FIXED 与 V2 完整 AA 开发牌局中发现：排序后的 JSON
checkpoint 恢复后，继续训练的结果与不中断训练不完全一致。Python 3.12 的本地
结果曾通过相同检查，不能代替 Python 3.11 的验证。

已在本机 CPython 3.11.16 独立复现。声明的开发发牌种子为 `71012`，训练 RNG
种子为 `71013`；先进行三轮，排序 JSON 保存／恢复，然后继续。两个编码版本均
在第五轮首次出现一个信息集不同：当时 RNG、节点数 2342 和信息集键完全相同，
regret 差最大约 `1.14e-13`，average 差约 `4.44e-16`。

根因是 regret-matching 归一化与平均策略导出使用 `sum(dict.values())`。
JSON 的 `sort_keys=True` 改变动作映射的插入顺序；Python 3.11 的逐项浮点求和
因此可能产生不同舍入。Python 3.12 改善后的浮点 `sum` 在该探针中掩盖了问题。

修正将上述两个归一化分母按动作 ID 的固定排序求和。没有改变收益、regret
公式、遍历顺序、采样动作顺序、抽象、训练种子、预算、对手或评估门槛。这是恢复
一致性修正，不是根据策略测试结果进行调参。原严格相等断言保留，不增加容差。

checkpoint、导出训练元数据及新冻结协议声明
`canonical_action_sum_v1_runtime_bound`。缺少该字段的旧 checkpoint 仍可加载，
用于保留和检查历史结果；不能据此声称跨数值实现的续训轨迹与旧实现相同。研究
执行器要求完整代码和依赖身份一致，原冻结研究不能原地接上新实现继续拟合。

## 证据边界

- 原始研究与 CI 失败保留；修正后需要重新冻结源码并按原定规则和预算重跑。
- V1_FIXED 与 V2 都应用同一数值修正。
- 回归除真实 Python 3.11 外，还显式注入逐项浮点求和，因此新版本 Python 不会
  再掩盖这个排序恢复问题；检查完整 checkpoint 和排序 JSON 字节表示严格一致。
- 数值轨迹仍绑定冻结的 Python 版本、依赖与运行环境，不承诺不同 Python 版本
  或不同平台间的逐位相等。
- 这些检查验证工程可复现性，不证明策略强度、新牌局覆盖率或实战收益。
