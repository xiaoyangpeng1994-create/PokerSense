# AA 八座工具：桌规、连续观察、问题记录与条件分析

本轮目标是准备实体手机＋采集卡的 AA 工具。软件侧新增可运行路径，不把条件模型、开发回归或打包成功称为真实视觉／策略验收。

## 用户流程

1. 打开 AA 专用程序，先检查资源包预检结果。页面打开不会访问设备。
2. 填写本桌大小盲、每人前注、straddle、抽水和封顶；未知留空。抽水输入3表示3%，封顶按BB倍数，金额保存为十进制字符串。换桌后清空并重填。
3. 选择明确来源后点击开始。现场需要启动时启用 `--allow-capture`，并选择设备编号和接口。开发回放会明确标为“非现场”。
4. 核对八座字段、当前牌面、原帧号、庄位、动作候选、开局状态及未解释现金差额。未知不会用旧值填满。
5. 发现问题时填写说明，点击“保存问题（含当前画面）”。只有点击才保存当前快照和匹配JPEG，位置由启动参数 `--records-dir` 指定。记录包含规则版本、来源、配置与资源包哈希；默认未审阅、不可直接训练或当独立验收。
6. 对已具备完整输入的支持场景，在单独的“多人河牌条件分析”中填写手工场景，或载入显式人工示例查看格式。可以选择使用本桌手动规则；不自动将未经确认的观察候选转成完整策略输入。
7. 停止、来源切换、规则改变、手工分析输入改变都会使旧结果失效。结束验证后停止并退出程序。

## 当前规则边界

手动规则是 `MANUAL_DECLARATION`，不是视觉事实。字段完整时只生成 `verification_status=simulation` 的条件分析配置。手动填写不能产生 `visual_verified` 或 `live_strategy_eligible`。

目前只表达无straddle、UTG强制straddle、UTG逐手确认的可选straddle；其他位置／倍数机制不得套成UTG。保险、暴击、种蘑菇未知时保留未知，开启时阻止普通条件分析使用该规则。视觉自动读取桌面盲注文本尚未实现；先使用本轮人工入口。

公开规则与平台规则分开：本轮实际查阅 [Poker TDA规则21/43/47](https://www.pokertda.com/view-poker-tda-rules/)，确认每个边池分别结算、加注通常按总额表达、最小加注以增量定义，以及累计短all-in可能对不同玩家分别重开。TDA是赛事规则参考，不能自行当作AA房间实际规则。现有条件三人内核不支持all-in跨越，终结内核不再有对手后续行动，所以不借这些新入口宣称已解决全街重开规则。

[PokerKit官方源码与示例](https://github.com/uoftcprg/pokerkit)提供多人、cash-game、前注与straddle规则环境，可作独立规则对照；[OpenSpiel](https://github.com/google-deepmind/open_spiel)用于策略算法实验。二者都不是已训练、可直接用于AA高盈利的策略。既有Pluribus及开源边界研究见 `AA-MULTIWAY-STRATEGY-RESEARCH-20260913.zh-CN.md`，本轮未训练或运行第三方solver。

## 连续来源

`--replay-playlist` 支持服务端指定的多段开发PNG清单。每段明确 pool/first/last/manifest_sha256/context_only；同audit、原帧连续、PTS严格递增，解码前核对全部选段元数据，读取时再验图片路径与哈希。浏览器不能改来源路径。

处理序号与原帧号分别保留，三帧开局前滚标记context_only，不计入完整手牌分母。原1470中途启动没有epoch的现象并非序号从0开始造成；包含1260–1262后，既有算法能在1263发牌后自动形成开局候选。原自动算法、阈值及资格门禁没有因此修改。

## 条件分析接口

迁移原主目录六个模块、五个CLI、示例、测试和失败报告到当前工作分支，没有导入Task7模拟资产或改变模拟/live隔离合同。

- terminal：6–8人桌，Hero当前唯一ACTIVE，2–7名已all-in对手，完整河牌，比较call/fold并计算边池、退回和配置抽水。
- threeway：6–8人桌，河牌开始恰好3ACTIVE，有限动作网格，明确响应权重及范围，不跨all-in/边池。
- 默认独立spawn进程，10秒预算；terminal最多4096联合组合，threeway最多128组合／20000节点。超时终止，不返回局部最优值；识别进程不等待分析。
- 分析绑定输入哈希、规则版本和观察generation；原始手工场景与有效规则可导出。示例中的Hero不一定为物理座位4，代表独立算例，不冒充当前桌。
- 固定策略压力筛选及对手校准的历史失败仍保留，不能用两个算例完成代表强策略或真实盈利。

## 采集和隐私边界

AA专用进程之间通过OS锁共享设备排他，索引及接口不同也不能重复占用。旧旁观录制锁存在时拒绝启动，但旧录制器不参与新锁，因此不能保证其稍后启动不会竞争；现场不要同时运行旧录制器或其他摄像头软件。

没有背景录制。问题记录是操作者点击时的一张派生JPEG加JSON；可能包含牌桌昵称等私有信息，留在本机目录，不上传GitHub。多页面／手工换桌不会将旧规则与旧帧混成新证据。
