# AA8 动作字形去重 V2

本轮修复 PR #3 人工复核确认的六个动作字形误报。实现只处理离线开发候选，
不生成合法动作菜单、范围模型、策略资格或 Advice。

## 为什么新增 V2

旧 `GlyphTransitions`、`aa8_action_transfer.py` 和
`aa8_visual_pipeline.py` 都属于 AA8 candidate V1 的 280 文件冻结清单。
本轮保留这些文件的原字节，新增：

- `aa8_glyph_transitions_v2.py`：遮罩与动作后动画安全的字形状态机；
- `aa8_visual_pipeline_v2.py`：离线开发回放入口。

冻结的 holdout harness 仍调用 V1。未来若要在新的保留集或真实设备验收中使用
V2，必须先建立新的候选冻结和独立评估协议，不能把本次开发结果回写成 V1
验收。

## 状态机合同

V2 保留 2 帧确认、5 帧稳定清除，并增加以下规则：

1. 不支持场景和特殊遮罩挂起状态更新；它们不计作清除。
2. 挂起时只保留已确认或已压制的字形身份，未确认的一帧候选不能与遮罩后的
   一帧拼成稳定证据。
3. 同座位刚完成动作后的 5 帧内，不同动作字形作为动作后动画压制；短暂空值
   不会解除压制，只有 5 个稳定清除帧才重新武装同一字形。
4. 足够晚且不同的动作仍可在没有清除字形时发出，避免把正常后续行动永久
   吞掉。
5. 状态机提供显式 `begin_epoch()`，但只有权威换手边界才可调用。当前自动
   `HandTransitionCandidates` 明确不是权威边界，因此 V2 主管线不会用它清空
   状态；跨遮罩换手后相同字形可能保守漏报，不能用自动候选换取重复误报。

任何被压制或无法区分的情况都只能减少候选，不会被转换成 fold 或其他扑克
事实。

## 结论边界

本轮只能说明：在这一个已人工复核的开发会话中，V2 精确去掉已知六个误报，
没有破坏 30 个已确认候选。它不证明未标注机会的召回率、完整合法菜单、跨会话
准确率、对手模型可校准性、硬件实时性能或实战盈利能力。真实对手校准仍因缺少
同规则多会话的完整决策机会而 BLOCKED。
