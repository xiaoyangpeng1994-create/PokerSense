# 三人 river 固定策略压力验证与有限候选校准 V1

本轮把策略开发推进到可重复的模型失配检查：先固定 Hero 在公开信息集上的动作，再更换对手范围和响应模型计算表现。测试世界不能重新优化 Hero。它仍是离线条件模型研究，不是完整牌局策略、真实对手校准或盈利验收。

## 两个新增模块

`threeway_policy_evaluation_v1.py` 的 `compile_policy_book` 只在规划阶段优化，冻结公开条件、规划场景哈希、公开历史到动作的映射和策略哈希。`evaluate_policy_book` 仅执行冻结映射；未覆盖历史按预声明规则免费 check，否则 fold。输出分别记录至少一次 fallback 的概率、fallback 次数期望及未覆盖历史，不能把次数当概率。

世界可以改变对手范围和响应参数；公开牌、Hero 手牌、费用规则、行动历史、动作网格等必须一致。额外测试模型可按对手自己的对子牌点和 Hero 最近公开 check 改变响应，用于暴露原类别/价格模型表达不了的行为。它不读取其他玩家的隐藏手牌来选动作。固定策略及 check/fold、check/call 基线共同受节点总预算约束，超限整份结果 BLOCKED，无部分 EV。

`response_model_calibration_v1.py` 冻结有限候选模型，以训练集 log loss 选一个候选，再仅验证该候选。并非连续参数拟合或范围学习。训练/验证按 session 和 hand 同时隔离，验证不能改选模型；零似然保留全部失败样本，log loss 为 `None` 表示无穷，Brier 仍计算全部样本。

数据源只允许分别使用 `synthetic` 或 `reviewed_all_decisions`，拒绝混用和 showdown-only 抽样。未知自身牌类别只能用于所有候选均不依赖牌类别的公共响应模型。每条决策的证据哈希、会话和牌局标识用于绑定内容，不能证明标签正确、完整采样、合法动作菜单或冻结时间。人工声明的数据也只给 `REVIEW_REQUIRED_NOT_EMPIRICALLY_APPROVED`；合成数据始终 `NOT_REAL_CALIBRATION`。

## 可复现实验

从仓库根目录运行，使用独立的新输出目录：

```powershell
$env:PYTHONPATH='src;.'
$env:PYTHONUTF8='1'
python tools/validate_threeway_models.py --input configs/strategy/examples/threeway-river-response-manual.json --protocol configs/strategy/examples/threeway-validation-protocol-v1.json --output G:/PokerSense_private/threeway_model_validation_20260914_v1/my-new-run
```

协议声明三种公共响应候选、分开的训练/验证种子、600 条训练和 400 条验证决策。生成器使用 calling 候选；这是一项模型内合成恢复实验。会话/hand group 是采样分组，不代表连贯的完整牌局。

先保存协议及候选，再生成训练、保存选择回执，之后生成验证并评分。6/7/8 人桌各有面对下注及尚未下注两个 river 根，每个根固定原手工模型和训练所选模型两本策略，共 12 本，全部保存后才开始世界评价。五个手工世界是原模型控制、强价值范围、弱跟注范围、对子牌点响应及公开 check 后激进响应，共 30 对/60 次固定策略评价。桌上人数变化不等于活跃人数变化：全程仍只有 3 个 ACTIVE。

负收益比较、fallback 和不完整案例全部保留。声明的筛选失败不影响工具工程正确性；即使筛选通过，仍固定输出 `NO_EMPIRICAL_PROMOTION`。动作网格外下注、all-in/边池跨越和更多活跃玩家仍不支持；模型族扩展没有解除这些边界。

## 独立校验及证据边界

独立反例中，规划 QQ 对弱 TT 得到 CALL、EV 160；固定同一策略后换强 JJ，仍 CALL、EV -100，而 check/fold 为 0。禁用优化入口后世界评价仍可运行。另一个牌点响应 oracle 得到历史概率 7/10、后验 9/14 与 5/14、固定 CALL EV -50/7。校准反例让训练支持 A、验证支持 B，结果仍选择 A；零概率验证不删失败样本。

新模块共用既有 V1 的合法转移、信念及结算内核，因此不是第二套独立结算实现。金额为预先指定 river 条件下的净增量 chips/BB，不能乘以 100 冒充全手 bb/100，也不为给定模型下的精确期望编造统计置信区间。实际盈利仍需要独立对手池、完整轨迹及净收益评估。

## 实测结果

最终 `run-v2/report.json` 完成全部 30 对、60 次评价，12 本策略哈希保持一致。`source-receipt.json` 绑定 16 项实现/协议/依赖/测试的运行前后哈希及产物哈希；初次 `run-v1` 保留，结果相同。训练选择 `calling_public_v1`，400 条独立合成验证决策的平均 log loss 为 0.8328094186，Brier 为 779687/1622400（约 0.4805763）。这里只说明有限候选选择恢复了合成生成模型，不说明学到了真实对手。

压力筛选结果为 **FAIL_STRESS_SCREEN**：30 个世界案例中 18 个至少输给一项比较对象，fallback 为 0。筛选同时比较原手工策略、check/fold 和 check/call，不能漏掉任何一项。6 人面对下注的原模型控制中，所选策略 EV 约 35.6915，比原手工策略低约 0.1607 chips；强价值世界所选策略 EV -80，相对原手工策略及 check/call 各低 60，相对 check/fold 低 80。未下注根的牌点响应和 check 后激进世界，也暴露了相对 check/call 的劣势。

这些是各自给定条件与假设下的反例，不将手写世界等权平均成代表性对手池成绩。`weak_callers` 使用所选模型响应，是事先声明的依赖候选的控制世界；不是独立真实对手。既有规划网格与预算仍约束所有结果，零 fallback 不证明能应对网格外动作。

下一步优先建立可审查的完整决策样本、公开行为响应及范围不确定性的校准/验证协议，再在预先固定的多组对手假设下比较候选策略。必须保留本轮失败案例作为回归，不能反复针对这五个世界调参后再称独立验证。真实牌类别通常仅在部分摊牌时可见，因此不能把摊牌子样本直接当全体对手范围。
