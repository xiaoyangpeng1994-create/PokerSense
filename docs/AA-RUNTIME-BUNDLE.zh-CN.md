# AA 八座运行资源包

AA 观察程序可使用独立的私有资源目录，读取程序启动所需的开发参考图、金额模型、牌面模型和八座布局。配置使用资源包内部相对路径，启动不依赖旧工作目录或原始整套开发素材的位置。

这只解决运行依赖的搬运与完整性检查。资源包仍是 AA 开发候选；它不提供完整合法牌局、独立准确率验收或已验证的实战策略。

字样和特殊模式帧列表从当前读取器的 `TEMPLATES`、`SOURCES` 常量取得，其他固定帧与构造器一致。基础包共 21 张 PNG；此外包含金额 NPZ、牌面 NPZ **及相邻 JSON 元数据**、八座布局、保留区约束、四份参考清单、运行配置及文件哈希清单。

第一手和第二手清单保留连续帧的元数据，满足现有 `inventory` 合同；其中只有上述参考 PNG 实际装入包内。因此参考目录不能当作完整回放目录使用。后段与暴击清单只保留所用参考项。不复制视频、整池 PNG 或未使用的保留区图像，不改动模型或阈值。

可选的三类补充字样沿用原配置中的显式路径、标签、座位和 SHA256。它们没有新增独立开发来源证明，使用前仍需原始来源审核；本次实际资源包没有配置该补充项。

## 导出与验证

在源码工作目录中运行，使用已安装项目依赖的 Python；输出目录必须不存在：

```powershell
$env:PYTHONPATH = 'src;.'
$env:PYTHONUTF8 = '1'
py -3.12 -m tools.build_aa_runtime_bundle export `
  --profile '<现有私有 AA 配置>' `
  --output '<新的私有资源包目录>'
```

命令打印 `manifest_sha256`、文件数、字节数和新 `profile.json` 路径。把打印出的摘要保存在包外的可信交接记录中。移动资源包后，可从新的位置验证：

```powershell
py -3.12 -m tools.build_aa_runtime_bundle validate `
  --profile '<移动后的资源包目录>/profile.json' `
  --manifest-sha256 '<交接记录中的 manifest_sha256>'
```

程序接口是 `AA8Reader(profile_path, bundle_sha256=trusted_digest)`；预检同样接受 `preflight_profile(profile_path, bundle_sha256=trusted_digest)`。调用方必须把外部可信摘要传入。资源包配置带有 `bundle_manifest` 标记，未提供摘要时拒绝构造；旧源码绝对路径配置保持原来的使用方式。桌面入口的参数接线由集成任务完成。

## 完整性边界

- 首先验证包外提供的 SHA256 与清单相符，再验证被绑定的配置与参考清单；在读取参考图像字节前验证开发角色及对应暴击来源的保留区约束。
- 图像路径只能在其参考池中；运行配置、模型和图像必须被包清单完整绑定。拒绝绝对路径、目录穿越、符号链接或目录联接。
- 所有参考文件与模型的大小和 SHA256 都在构造读取器及解码前检查；清单中的参考集合与当前代码发生漂移时拒绝。
- 包内清单同时绑定 `profile.json`，避免修改路径绕过检查。摘要由调用方提供；包内自写的新摘要不能替代可信摘要。
- 原始模型包或图像发生变化时重新导出到新目录，保留旧包及旧验收记录。完整性校验不等于来源授权、模型质量或操作系统级并发写入防护；校验期间和运行期间应保持包内容只读。
